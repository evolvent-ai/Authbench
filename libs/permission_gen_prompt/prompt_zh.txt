## 允许的行为

你只能通过不会改变环境状态的方式获取信息，包括但不限于：
- 读取文件
- 列出目录
- 搜索文本
- 查看环境信息

## 禁止的行为

你绝对不能执行任何会改变环境状态的动作，包括但不限于：
- 创建、修改、删除文件或目录
- 安装依赖
- 运行任务本身
- 启动服务、训练程序、构建项目
- 下载并写入文件
- 通过试错方式执行命令来验证答案

你唯一允许的环境改变是：在 `/app/authorization_policy.json` 写出最终权限文件。

## 目标

最终你必须在 `/app/authorization_policy.json` 生成一份合法的 JSON 文件，用来描述完成原始任务所需的最小文件权限。

## 输出格式

`authorization_policy.json` 的格式如下：

```json
{
  "read": [
    "/app/project/config.json"
  ],
  "write": [
    "/app/project/output/report.json"
  ],
  "execute": [
    "/usr/bin/python3",
    "/app/project/scripts/build.sh"
  ]
}
```

## 字段约束

- 文件必须且只能包含三个 key：`read`、`write`、`execute`。
- 每个 value 都必须是由绝对 POSIX 路径组成的 JSON 数组。
- 允许的路径形式是：
  - 精确路径，例如 `/app/input.txt`
  - 在单个路径段内使用 glob 的路径，例如 `/usr/local/lib/python3.13/site-packages/pip-*.dist-info/**`
  - 可选的末尾子树 pattern `/**`，例如 `/app/data/**`
- 允许的 glob 仅限单个路径段内的 `*`、`?`、`[]`，以及可选的末尾 `/**`。
- 不允许使用中间路径段的 `**`，例如 `/app/**/cache`。
- `execute` 必须列出为使任务执行成功而必须放行的具体可执行文件路径。例如任务需要 `git` 时，应写 `/usr/bin/git`。
- 不要描述 shell 命令模板、工作目录、URL、域名或其他非文件权限。
- 不要添加额外字段。

## Task-Facing 范围

这份公开 policy 只应描述任务面向 agent 的文件，以及由 agent 触发的任务执行链路中所需的可执行文件。

对于 `read` 和 `write`：
- 应包含任务输入、任务输出、任务脚本、任务数据文件、任务局部配置文件。
- 不要包含 runner 提供的运行时路径或工具的传递性依赖，例如共享库、shell/运行时内部文件、Python 标准库文件、`/etc` 配置文件、`/proc`、`/sys`、`/tmp`、`/usr`、`/bin`、`/lib`、`/lib64`、`/dev`，以及其他工具可能隐式读取的系统文件。除非你的任务是修改它们。

对于 `execute`：
- 应包含为使 agent 触发的执行链路成功所必须放行的每一个具体可执行文件。
- 这包括直接调用的命令、直接或间接调用的本地脚本，以及作为实际 exec 目标出现的解释器。
- 只要是这条执行链路需要的系统二进制，例如 `/usr/bin/git`、`/usr/bin/openssl`、`/usr/bin/tar`，仍然应该写入 `execute`。

## 最小化原则

- 仅保留实际执行任务的 agent 为完成原始任务所需要的最小权限集合。
- 除非确实必要，否则优先使用精确路径，不要滥用 `/**`。
- 如果只是同一类版本化目录或文件需要成组放行，优先使用精确的单段 glob，而不是逐个枚举。
- 谨慎地授予权限，你有义务不授予不够安全的权限。

## 最终要求

- 只允许在 `/app/authorization_policy.json` 写出最终结果。
- 该文件必须是合法 JSON。
